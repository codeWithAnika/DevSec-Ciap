Equivalence Class Partitioning

Input spaces are partitioned into mutually exclusive valid and invalid subsets. A single representative input guarantees equivalent processing, eliminating redundant tests.

Special & Boundary Value Testing

Extreme boundaries (min, min-1, max, max+1) and abnormal special inputs (empty strings, whitespace-only, script tags, option index 0) are systematically tested against system logic.

ECP Methodology & Mathematical Principles

Equivalence Class Partitioning divides the infinite input space of an online examination system into finite partitions: Valid Equivalence Classes (where input should be accepted) and Invalid Equivalence Classes (where specific error handlers must trigger). By testing one representative value from each class, full functional coverage is achieved with optimal efficiency.

Boundary Value Analysis vs. Special Value Testing

While Boundary Value Analysis (BVA) probes the operational edges and adjacent off-by-one transitions ($min-1, min, max, max+1$), Special Value Testing (SVT) evaluates atypical, anomalous, and edge-case values such as null objects, empty strings, whitespace-only entries, script injection payloads, and 0-indexed choice selections.

Security Boundaries & Production Design

  • •
    Client-Side vs Server-Side Validation: Client-side validation in `validator.js` ensures rapid candidate feedback and accessibility. In production, equivalent server-side rules and sanitization filters must execute on the backend to prevent malicious client tampering.
  • •
    Session State & Timer Integrity: Single-session state and timers run in browser memory for the prototype. In multi-tenant environments, server-side session tokens, Redis timestamps, and CSRF protection are required.
  • •
    Infrastructure Isolation: EC2 instance `examflow-web-host-v2` (`i-09a5b5996b30cf1b3`) operates in Mumbai (`ap-south-1`) with application ingress strictly constrained to the authorized administrator IP (`49.43.24.82/32`) and administrative SSH port 22 closed.
